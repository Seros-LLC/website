Home page:

  "@context": "https://schema.org",

## Brand and SERP findings

- Search for "Seros AI consulting" returns Sero AI (agtech, YC guardrails startup), seroai.pro (also "AI consulting and automation"), Seros Inc (seros.com, IT services). seros.dev does not appear.
- Search for "seros.dev" returns the GitHub repos `Seros-LLC/website` and `Seros-LLC/seros`, not the site.
- Implication: the site is likely not indexed yet or has no authority. Search Console + sitemap submission is step one.
- Use "Seros, LLC" or "Seros AI consulting" consistently in titles, schema `legalName`, and external profiles to disambiguate from "Sero AI".
- Create a LinkedIn company page and add it to `sameAs`. Link seros.dev from GitHub org profile and both repo "Website" fields (the spec repo already does).

## On-page content

- H1s are distinctive but contain no search terms: "Make AI useful. Keep people in control.", "A build you can examine, not a result we cannot prove.", "Know what you are buying before we build." Keep them, but put the keyword in the eyebrow/kicker as an `<h1>` companion, or make the kicker part of the title. Example on `/services`: kicker "AI consulting services" above the H1.
- Target terms the site can honestly own: `AI consulting`, `agentic workflow automation`, `AI readiness assessment`, `AI-native CRM`, `human-in-the-loop AI agents`, `AI consulting for small business`.
- `/offerings` lists 300 names with no descriptions. Long term, the 6 core services each deserve a dedicated page (e.g. `/services/ai-readiness-assessment`) with 600-1,000 words: what it is, deliverables, timeline, price model, what it is not.
- A small "Notes" or "Guides" section (e.g. "Where AI agents are not worth it") fits the brand voice and earns links. No blog exists today.
- Local option, only if wanted: a Georgia footprint (`ENTITY_ADDRESS` is Georgia) supports "AI consulting Georgia" pages. PRODUCT.md says no target market is claimed publicly, so this is a business decision.
