The in-house product

Our first build was an in-house, human-confirmed AI workflow: a Slack-to-Linear delivery workflow that read only the channels an administrator explicitly selected, identified commitments in those conversations, drafted the corresponding tracker work, and refused to write anything until a person reviewed and confirmed it.

Status: paused. The implementation is retired. Seros now offers consulting and build engagements rather than product seats. The record below describes the build, not a service currently available to buy.

Engineering decisions in the build

CapabilityHow it shows up in the build
Third-party integrationSlack integration with signed-request verification on every inbound event, and a server-side Linear client with its credential held only in production configuration
Multi-tenant isolationEvery query is scoped to a workspace, enforced by an automated check that fails the build if any module reaches past the scope boundary
Human-in-the-loop AIA model proposes; a task row can only be created from a recorded human confirmation. There is no code path that skips it.
AuditabilityWorkspace actions are written to an audit log that database triggers make append-only, and every model call is metered against a per-workspace budget before it runs
Fail-closed operationsThe application refuses to boot in production unless its required configuration is present and valid
Test disciplineTypecheck, tenancy check, offline unit tests and a scored evaluation set, chained into one verification command

Read the record

The public specification repository preserves the architecture and implementation record. Use it to examine the design decisions behind the capabilities above. There are no client testimonials, benchmarks or claimed business results attached to this work.

How we work, in four rules

  1. Nothing consequential happens without a person deciding it.
  2. Scope is written down before code is written, and the written scope wins.
  3. A claim we cannot verify does not ship, in software or in a status report.
  4. You own the code, the infrastructure and the credentials. There is no lock-in to us.
